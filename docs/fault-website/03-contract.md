## Server/API contract (Codex retains)

POST /api/waitlist `{email,consent:true,website:'',attribution:{first,last},visitorId?:UUID}`; reply202 `{state:'pending',message}` generic for duplicate/suppressed/active records.400 validation,429 throttle,503 setup/service failure; never pretend email sent before provider acceptance. DB saves pending + consent version/time + sanitized attribution and encrypted email outbox atomically. Email canonical rule trim, ASCII email validation, lowercase mailbox/domain, preserve dots/plus. Creation once per unique canonical address. Random256-bit tokens, only SHA256 digests in token table; encrypted outbox for retry.24h confirmation, unsubscription link365days; scanners' GET does not consume. Fragment URLs keep token out of server URL logs; client clears fragment and requires explicit POST button. Expired/invalid/used clear states; replay never recreates event. Unsubscribe revokes pending confirmation tokens and queued email, subtracts eligibility immediately. Repeat unsubscribe returns safely. Rejoin needs new consent and confirmation, never overrides suppression.

POST /api/confirm `{token}` -> `{state:'confirmed'|'used'|'expired'|'invalid'|'unsubscribed',message}`. POST /api/unsubscribe same payload -> `{state:'unsubscribed'|'expired'|'invalid',message}`. Every mutation same-origin check+body limit+JSON validation, no secret/raw input logging. Trusted proxy IP only in hosted context; HMAC IP buckets plus independent canonical-email limits. Service-role credentials only Node server adapter. Fail closed unconfigured; no in-memory fallback in deployed app.

POST /api/webhooks/resend raw verified Svix payload; authenticate first, retain only minimal deduplicated event metadata, handle email.bounced/complained/suppressed, suppression.added/removed, contact.updated unsubscribed. DB receipt and state update atomic. Delivery cannot clear suppression. Older provider removal cannot overwrite later suppression; complaints/abuse require manual clearance. Retries never double-count. Public subscriber count is not exposed; service-only SQL count excludes pending, unsubscribe, duplicates, abuse, internal tests and known suppression. Cron/dispatch bearer-only; leased durable jobs use stable provider idempotency keys; retry within23h, exponential backoff, terminal failures visible. Analytics outbox events use deterministic UUID insert ID; retry at-least-once with backend dedupe, no exactly-once transport claim.
