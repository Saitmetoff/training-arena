2026-08-31 (`docs/release/LAUNCH_PLAN_2026-09-20.md` §2), and Play requires
16 KB page-size support for apps targeting Android 15+. The old baseline
(Flutter 3.24.5, AGP 8.1.0, Kotlin 1.8.22, Gradle 8.3, compile/target 34)
satisfies neither.

## 4. Release-only defects found by the runtime smoke (and fixed)

The first release APK **crashed at startup** on API 36 (`Unable to get
provider androidx.startup.InitializationProvider: Failed to create an instance
of androidx.work.impl.WorkDatabase`), and ML Kit logged
`NoSuchMethodException: …PoseRegistrar.<init>`. Root cause: R8 shrank
reflectively instantiated constructors that old consumer rules do not keep
(Room 2.2.5 `-keep class * extends androidx.room.RoomDatabase` without
`<init>()`; ML Kit pose-detection ships no registrar keep). Fixed in
`app/android/app/proguard-rules.pro`:

```
-keep class * extends androidx.room.RoomDatabase { <init>(); }
-keep class * implements com.google.firebase.components.ComponentRegistrar { <init>(); }
```

After the fix: API 36 emulator launch is crash-free with no ComponentDiscovery
warnings (`qa/launch/l02/api36_runtime.txt`), and the app also launches on the
16 KB page-size emulator (`qa/launch/l02/api35_16k_runtime.txt`).

## 7. Blockers and follow-ups

- **R9 (signing) is the only artifact blocker.** No keystore exists; the AAB is
  unsigned and the APK is debug-signed. Everything else in the build path is
  verified. The moment the owner creates the upload key (CONFIGURATION.md §3)
  the `release-candidate` job produces the signed AAB + APK and the
  upload-key/Play-cert pins become meaningful.
- **R14 (follow-up):** Flutter 3.47 warns the app and `shared_preferences_android`
  still apply the Kotlin Gradle Plugin; a future Flutter will require built-in
  Kotlin (`android.newDsl`/`android.builtInKotlin` flags are the current
  compatibility shims). Migrate before the next major Flutter upgrade.
- Local Windows builds need `kotlin.incremental=false` +
  `kotlin.compiler.execution.strategy=in-process` until the Kotlin 2.4.0 daemon
  cache bug is fixed upstream (documented in `gradle.properties`).
- Physical-device API 24+ and camera/pose runtime checks remain L04.
