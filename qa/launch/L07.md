## 3. External deletion route (verified end to end)

`challenge-web/delete-account.html` + `delete_account.js`:

- ownership is verified with the same email one-time-code flow the app uses
  (`POST /auth/v1/otp` with `create_user:false`, `POST /auth/v1/verify`);
- the verified session lives in the closure only — no cookie, no storage, no
  analytics, no console logging, so no token or code can reach a log;
- the delete call is the existing `{action:"delete_account"}` with the
  verified bearer; a network failure keeps the session for a safe retry, a
  401/403 reports the already-processed/expired state without claiming a
  second deletion.

Evidence `qa/launch/l07/deletion_route_e2e.txt` (exit 0) runs the **shipped
client** against the local stack: account created (200) → code requested with
`create_user:false` (200) → code read from the local mail catcher → verify
(200) → `delete_account` (200) → the auth user is gone (`GET /auth/v1/user`
403). The trace contains method, path and status only.
