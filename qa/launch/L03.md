## 2. What changed

- `app/lib/battle/runtime/battle_controller.dart`: new
  `rankedMatchmakingEnabled` flag (default `true` for existing test hosts);
  `startRankedSearch` refuses with an honest notice before any queue state,
  analytics or backend call. Friend challenges, inbox, link acceptance and an
  active match are untouched.
- `app/lib/battle/runtime/battle_runtime.dart`: `BattleRuntime.fromConfig`
  passes `config.rankedMatchmakingEnabled` into the controller (composition
  root).
- `app/lib/battle/ui/battle_tab.dart`: reads `ArenaConfigScope`; the ranked
  action renders only when ranked **and** camera counting are on. Otherwise an
  info banner replaces it ("does not include ranked matchmaking" / "does not
  enable camera counting, so ranked battles cannot be scored") and the footer
  stops claiming live camera battles when camera counting is off.
- `app/lib/account/auth/auth_store.dart`: `SecureAuthSessionStore` +
  `SecureKeyValueStore` port + `FlutterSecureKeyValueStore` (new dependency
  `flutter_secure_storage: ^11.2.0`, Android Keystore AES-GCM/RSA-OAEP,
  API 23+). Legacy `arena.auth.session.v1` / `arena.auth.pkce.v1`
  SharedPreferences values are migrated on read; the plaintext copy is removed
  **only after** the secure write succeeds. A failed secure write throws
  `AuthStorageException` (never a plaintext fallback or a silent "saved"); a
  failed migration keeps the legacy value and still returns the session; a
  failed read degrades to signed-out; a failed delete is reported after the
  legacy copy is removed.
- `app/lib/account/auth/supabase_auth_gateway.dart`: secure-write failures map
  to `AccountException('storage', '<plain sentence>')` for sign-in and PKCE
  state; internal failure paths clear quietly so the real provider error is
  not masked. `signOut` still clears secure+legacy first.
- `app/lib/account/runtime/account_runtime.dart`: production store is
  `SecureAuthSessionStore()`.
- `app/lib/account/runtime/account_controller.dart`: **successful** account
  deletion clears the durable session (`_auth.signOut`) before clearing local
  state; a failed deletion still keeps the session for retry (unchanged).
- `app/android/app/src/main/AndroidManifest.xml`: `android:allowBackup="false"`
  (no cloud backup / device transfer of any app data).
- Audited, unchanged: camera gate (`battle_runtime.dart:61`), preview gate
  (`FixturesBattleBackend` refuses every competitive action; preview is a
  labelled composition path), push gate (`notification_runtime.dart:35`),
  challenge gate (`challenge_entry_controller.dart:659`) and the result-sharing
  factory guard (`arena_app.dart:136`, task-05 text fallback preserved).
- Tests: `app/test/battle/ranked_flag_test.dart`,
  `app/test/battle/battle_ranked_gate_widget_test.dart`,
  `app/test/account/secure_auth_store_test.dart`, gateway storage-failure test,
  delete-clears-session assertion and the `allowBackup` manifest assertion.
- Docs: `docs/decisions/07-matchmaking-incident-control-proposal.md`,
  `docs/release/CONFIGURATION.md` (flag rows + session storage/backup),
  `docs/release/GO_NO_GO.md` (L03 note, R10/R11a closed, R15 added).

## 4. Backend incident control — audit result and proposal

No operational server switch exists: `arena_queue_join`/`arena_queue_poll`
enqueue unconditionally, `arena_maintenance()` only expires and ticks, and
there is no flags table or operator RPC. Build-time dart-defines cannot stop
installed builds, so L03 does **not** claim one.

Proposal (not applied): `docs/decisions/07-matchmaking-incident-control-proposal.md`
— one additive `arena_controls` singleton table, a pause check in
`arena_queue_join`/`arena_queue_poll` using the existing `AR021 → forbidden`
error path (no wire or client change), an operator SQL snippet, pgTAP test
cases and a rollback note. Owner decision needed before launch (R15).
