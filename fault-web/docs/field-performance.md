# Fault field measurement contract

Targets: real-user p75 LCP <= 2500 ms, INP <= 200 ms and CLS <= 0.1. Lighthouse is lab evidence and cannot establish these percentiles. Missing INP observations mean unavailable, never zero.

Samples cover consenting visitors and supported browser APIs. They are a consented cohort rather than every visitor; missing consent/unsupported metrics are unavailable, never zero.

The landing page uses Next's installed `useReportWebVitals` hook with a stable callback. The callback sends only after optional analytics consent. It sends the anonymous visitor UUID plus `name`, generated numeric `id` and `value` for LCP/INP/CLS. It discards URLs, query strings, fragments, entries, element selectors, emails and tokens. No attribution fields are accepted at this endpoint. Consent revocation prevents subsequent sends; metrics that occurred without consent are not replayed.

`POST /api/vitals` accepts JSON from the exact configured origin, checks the bounded payload, validates an allowlisted metric and ID shape, and throttles requests by a keyed IP bucket. The server queues `web_vital` through the existing encrypted/durable waitlist outbox provider. The event properties are `metric_name`, `metric_id`, `metric_value`, `route: landing`, `internal_test`; the provider adds `site: fault`, `environment`, an idempotent `$insert_id`, `$process_person_profile: false` and `$geoip_disable: true`. Provider retries reuse the outbox ID. Multiple updates for the same metric ID are legitimate; retain the latest measurement per metric ID before computing percentiles. No raw performance entries or full page URLs leave the browser.

Field reporting requires the same configured server/database and a PostHog project ingestion key. Accepted events flush up to four durable jobs after the response. `vercel.json` prepares a protected daily sweep at `/api/internal/cron`, using server-only `CRON_SECRET`; the existing POST dispatcher remains available for controlled recovery. The daily schedule fits the current free-plan limit and is a backstop, not a promise of five-minute retries or 30,000-message throughput. Reporting is prepared in code but not operational while live delivery/server configuration is incomplete. No paid measurement plan was purchased. The existing development funnel remains separate from performance distributions.

For a production measurement report: select events named `web_vital` with site `fault`, environment `production`, route `landing`, and `internal_test = false`; group by `distinct_id`, `metric_id`, `metric_name`, take the latest `metric_value` by timestamp, then compute p75 by metric name. Report sample count, time window and device class if a deliberately approved bounded device-class property is added later. Current payload does not include device class. Do not mix synthetic/local, preview or internal-test events into field results. Require a meaningful representative sample before claiming targets met.
